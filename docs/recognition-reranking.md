## 对照范围

保留现有 BioCLIP v1 全参考检索作为第一阶段，按原始分数取最多 50 个不同植物参考。
第二阶段仅对这些候选重新排序，不手工插入人工确认的物种，不使用用户图片训练。
候选池没有召回正确物种时，重排无法补救。

`CatalogRecognitionProvider.recognize()` 在线仍默认返回 5 个候选。
新的 `retrieve(limit=50)` 仅供离线对照，硬上限 100。
`recognition_rerank.py` 使用新模型同时编码图片和候选学名，不复用 v1 文本向量。
文本策略为从 pybioclip 模板中固定选择的 3 个照片描述模板平均，
用同一组模板处理所有候选，不为目标物种定制提示，不编造中文名或物种介绍。
这是控制 CPU 文本编码成本的实验配置，不等同于官方 80 模板完整评测。

第二阶段不能把第一阶段的非植物/低细节拒识改成成功；原始阶段结果、分数及排名保留。
新分数仍为余弦相似度，`confidence` 为 null，不是正确概率。
结果明确标为候选池内重排，不宣称对完整 BioCLIP 2 参考库检索。

## 固定模型

- 模型：`imageomics/bioclip-2`，官方模型卡标明 MIT。
- Revision：`2957b322090f9cb17ae72c71981c7218a28d81e0`。
- 架构：ViT-L/14，图像 224、联合特征 768 维。
- 文件：`open_clip_model.safetensors`，1,710,517,724 字节。
- SHA-256：`b7b2bf6fbc95799e42630e394cf95803892ab447c1a8ab629dbc82fbeaf7dfef`。
- 本地位置：`server/.cache/models/bioclip-v2/open_clip_model.safetensors`。

官方来源：`https://huggingface.co/imageomics/bioclip-2`。
文件和配置都使用上述固定 revision，不跟随 `main` 自动升级。
校验完整文件后才能加载；仅读取本地 safetensors，不执行远程代码或自动下载。
模型许可不等于上游训练照片的再分发许可，本实验不下载训练照片。

默认预处理采用官方配置的 bicubic/shortest 与 CLIP 归一化（中心裁剪）。
可用 `--rerank-view whole` 对照整图方形缩放；它保留整张照片，但会拉伸非方形图片。
两者均使用固定 224 输入，不声称增大上传文件就能自动增加模型可见细节。
这与当前 v1 的整图方形缩放不同，因此本次比较的是两种完整流程，而非只替换一个权重变量。

## 运行

先准备并校验模型文件，沿用锁定的 `recognition` 依赖，无须新增库：

```sh
uv run --project server --extra recognition --locked --offline \
  yizhu-recognize client/src/assets/photos/ginkgo-leaf.jpg \
  --rerank --threads 2 --repeat 2 \
  --output .artifacts/recognition/rerank-comparison.json
```

`--rerank` 不能与手工 `--labels` 同用。输出拒绝覆盖，报告权限为 0600，
只使用匿名输入编号，不写原始文件路径、照片链接或账号标识。`.artifacts/` 不提交 Git。
授权的私人样例不复制到测试夹具、源码、文档或外部服务。

对照分两阶段顺序加载模型，减少实验进程内存压力。
报告分别记录检索耗时、重排首次调用（含文本编码）、文本缓存命中后的重排耗时和进程峰值。
文本缓存有容量上限；后续案例可能命中已有候选，所以首次调用不一定全冷。
**顺序加载的峰值不是在线同时常驻两个模型的内存开销，缓存命中耗时也不是端到端延迟。**
