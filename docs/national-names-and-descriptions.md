## 匹配规则与实际覆盖

- 中文首选名优先使用全国名录；已按明确要求从 ScienceDB 补充 8,438 个缺名物种，
  来源分开记录，不冒称全国名录。仍缺名的条目保持不可见。
- 按学名、等级精确匹配；不对类似拼写做模糊纠错，不把属名套到具体物种。
- 全国文件没有异名字段，不再使用外部异名桥接；存在歧义的名称跳过。
- 全国名录提供 **11,278** 个植物参考条目和 **4,044** 个中文浏览节点的名称；
  全国版本为 `CoL-China-2026-v2`。经 ScienceDB 补全，当前共有 **19,716** 个可见物种。
- 48,356 条全国记录不是 48,356 个模型已覆盖物种；不为了提高统计数字而硬匹配。
- 不保留手工配置别名。现已通过有来源数据补入“桂花”“荷花玉兰”等别名，
  `Osmanthus fragrans` 首选名仍为“木犀”，`Magnolia grandiflora` 仍为“荷花木兰”。
  应用规则见 `name-enrichment.md`；私人植物昵称不改写。
- Species ID、原始 taxonomy、向量行映射、分类节点 ID 和成员关系均在切换前校验未变。

`colchina_names.py` 是针对固定快照的标准库 XLSX 读取器：验证尺寸/SHA-256、
表头和行数；限制解压 XML 大小；不解压路径到磁盘，不执行公式、宏或外部链接。

## 两种描述，分别保存

### 我的描述：某一株的私人记录

`Plant.description` 为可选字符串，最多 1,000 字，保存在既有私人 SQLite 文档中。
建档或“编辑植物档案”均可填写；支持修改和清空，重登/重启后保留。

- 与 `Plant.story`、`Observation.note` 分开。
- 与物种名称的确认/修改无关，不被物种介绍覆盖。
- 所有写入仍使用可信登录上下文验证所有权。
- 旧客户端未发送 description 时，编辑其他字段不会清空已保存的描述。
- 仅纯文本显示，不执行用户输入的 HTML；日志不记录正文。
- 不能通过此接口写入共享 `Species.knowledge`。

### 物种简介：带出处的公共参考资料

`Species.knowledge` 单独保存 `summary`、`sources`、`isAiGenerated`、`reviewStatus`、
`updatedAt`。识别结果、名录详情与植物档案共用 `SpeciesKnowledge` 展示组件。

当前接入 **6 个简短摘要**：银杏、向日葵、绣球、龟背竹、酢浆草、白车轴草。
它们依据已读取的 NC State Extension / USDA 原始植物资料做少量事实摘要，
**标记为 AI 辅助整理、尚未人工校对**，不是复制完整文章，也不包含食用、药用或安全处置保证。
每条具体出处在 `server/src/yizhu_server/data/species-knowledge.json`。
其余条目保持 null，不用分类模板冒充完整形态介绍。

导入时校验摘要长度、出处 URL/标题及生成/复核状态。新增资料须保留出处与真实状态，
不要用识别模型自述或用户私人描述自动生成公共百科。

## 重建与部署

准备 TreeOfLife 文件和上述全国 XLSX 后：

```sh
uv run --project server --extra recognition --locked yizhu-catalog \
  --output server/.cache/catalog/treeoflife-10m/catalog-next.sqlite3
```

`--national-source` 可指定该全国文件的位置。物种简介默认来自版本化 JSON。
工具拒绝覆盖已有输出。检查名称/简介数量及 ID 不变后，原子替换公开参考库，再重启 API。
私人描述是 JSON 文档的可选字段，无须重建或迁移用户数据库。
上述命令仅生成全国基库；当前线上补充名称的重建还需依次执行别名及 ScienceDB
首选名补全步骤，见 `name-enrichment.md`，避免重建时丢失补充名称和可见性。
