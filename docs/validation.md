## 测试覆盖的领域约束

1. Mock 的来源、版本、演示标记与可空置信度。
2. 不依赖页面存在的任务状态推进。
3. 失败重试保持识别 ID，不重复产生任务记录。
4. 物种未知也可建档并形成首次观察。
5. 用户确认不改写 provider 原始结果。
6. 重复提交幂等、重名个体 ID 不相同。
7. 关联现有档案需要调用明确操作，且不覆盖已有物种。
8. 追加观察不改变植物 ID 或个体数目。
9. 本地 mock owner 隔离与越权 ID 拒绝；不是云端鉴权证明。
10. 必填、长度、运行中建档等校验。
11. 清空时不被尚未完成的任务重新填回数据。
12. 订阅更新与取消订阅。
13. 样板拒绝调用真实 provider。

尚无 UI 交互自动化覆盖率或真实服务器权限测试；不编造百分比。

## 静态设计检查的准确边界

使用自建静态适配层，把 Taro 的 View/Text/Image/Button 映射成仅供评审的 HTML。页面业务源码不使用浏览器 DOM；该适配层不进入小程序。

Chromium 原生 headless 窗口实测最小 viewport 为 500px，最初 viewport 断言失败，因此改为**明确设置并读取 320/375/430px 页面容器宽度**。27 项结果指容器布局，不是手机视口仿真。校样假设正常图片已载入；缺图检查另读实际图片的 naturalWidth。

浏览器检查只覆盖静态布局、换行和图片加载，不验证按钮、微信导航、相机、相册、权限、系统字体缩放、微信胶囊、原图预览或安全区。`three-pages.png` 不是微信截图。

## 后续真实环境检查步骤

不要求现在安装微信开发者工具；非 GUI 的官方预览/上传路径尚未核实与配置。先确认真实 AppID、开发者权限与可用的官方预览方案；密钥若需要，应只在用户本机安全配置。

拿到真实微信预览入口后，应按以下顺序记录设备、系统、微信版本与结果：

1. 打开首页，检查状态栏/胶囊、字号、长文本、底部安全区和图片加载。
2. 相机与相册分别验证允许、拒绝、取消、再次请求、照片超限与完整图预览。
3. 示例图分别切换成功、失败、无法判断，验证重试与返回首页后继续查看任务。
4. 不确认物种建档；手动选择物种后再建档，确认没有把候选自动当成结论。
5. 创建同昵称的两个个体，确认 ID 不同；在已有档案追加观察，确认 ID 不变。
6. 从结果关联已有档案，确认出现“是否同一株”提示且不会覆盖档案物种。
7. 清空会话并访问旧页面，检查回退路径；重启后确认恢复示例、用户临时数据不再出现。

正式上传预览、提交备案、审核、发布或开通收费资源，仍需分别获得用户确认。当前未执行这些操作。
