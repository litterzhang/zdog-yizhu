# 多肉物种扩展执行记录

更新日期：2026-10-05。

## 目标与边界

将公众号图谱中的原文名称映射到稳定的物种级分类单元，扩展当前249类BioCLIP 2闭集模型。模型只输出物种，不把园艺品种、商品名、杂交组合或属级统称当作独立类别。只有能可靠归并到单一物种、具有分类来源且有合规训练图片的目标才可加入支持元数据。

上线门槛保持为封存独立集宏端到端Top-1 > 80%、Top-5 > 90%，并要求全部新增类别各有独立样本。开发集、历史独立集或公众号图片不得充当最终验收集。

## 输入盘点

来源文章标题声称“270种”，正文实际解析出263个唯一名称和263张一一对应图片。提取记录位于：

`server/.cache/research/wechat-succulent-atlas-20261005/`

公众号图片没有开放训练许可，已标记为`reference-only-not-training-eligible`，只用于名称与图片关系核对，不进入训练或独立验收。

## 映射策略

1. 优先采用现有中国生物物种名录本地化目录中的物种级精确名称。
2. 园艺名称仅在来源能证明其唯一归属于一个物种时，作为该物种的来源别名；不创建品种类别。
3. 杂交种、亲本不唯一的商品名、同名异物及只能确定到属的名称一律不进入模型目标集。
4. 科学名继续通过权威分类服务核对接受名、等级和同物异名；名称相同但文章图片明显不是该物种时拒绝自动匹配。
5. 训练图片仅从许可兼容的开放来源采集，并保留来源、许可、作者组、图片哈希和去重证据。

## 训练与上线流程

- 先冻结新增物种清单和训练/开发图片快照；
- 复用同一BioCLIP 2编码器，逐轮训练扩展分类头；
- 每轮记录类别数、样本数、配方、宏Top-1/Top-5、逐类召回和失败分析；
- 达不到门槛时只根据开发结果改进数据或配方，不反复窥视封存终验集；
- 独立集达标后生成不可变生产元数据，注册新solution并切换服务；
- 分别验证本机Provider、本机健康接口和公网健康接口，不把服务健康等同于微信真机验收。
