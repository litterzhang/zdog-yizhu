## 如何避免重复上次的偏差

### 1. 不将“好种”理解为“常见”

工作簿的“了解程度”列多数是“好种”，这是分类判断。
真正的常见度信息在“说明”列，程序只读取明确的首句标签：
“极常见”“常见”“多见”“少见”“极少见”“近年未见”等，分别保存。

实际核对：

- 上海野生表明确“常见”142 条、“极常见”122 条，共 **264 条**，与论文报告相符。
- 上海栽培表明确“常见”270 条、“极常见”1 条；这些条目仍可能包含品种。
- 未标明频度、仅推荐适生、仅列为产品，不自动升级为“常见”。

在去重后的候选标签中：
**462** 个有“常见/极常见”记录，**497** 个有“多见”记录，
**310** 个有城市绿化推荐记录。这三组会重叠，不能相加当作独立物种数。
优先核对集还含盆栽产品及室内用途的名称级线索。

### 2. 不拿园艺品种凑物种数量

1,370 条品种、种下等级或带品种引号的记录暂不进入物种候选池，
原始记录保留在审计文件中，不删除，也不擅自并入父物种。
其中栽培工作表本身就有 1,194 条品种。

去重只使用明确的本地学名标签匹配；对 PDF 换行和作者名做保守处理，
不按昵称、模糊学名或相近中文名称自动合并。
杂交分类单元、未对齐的学名与商品名继续保留待核对状态。

全部候选中的 **2,341 个**能按学名标签对齐本地目录；
其中 **124 个**匹配到现有隐藏条目，保留为资料完善线索，未修改可见性。
剩余条目没有因当前数据库缺名或匹配失败而被丢弃。
这些是标签对齐，不意味着已完成接受名/异名关系审核。

### 3. 来源和地域不伪装成全国分布

1,260 个优先核对标签中，有 **871 个目前只有上海来源**。
当前材料主要覆盖华东、华北、华中、东北，不能声称已经全国均衡。
华南、西南、西北的场景证据、室内园艺、农作物仍需定向补充。

“原生适合绿化”不等于“实际到处栽种”；来源中的荒山推荐也不等于城市街道常见。
程序从表格的“城市绿化”列提取城市推荐标记，未将所有乡土条目无差别列为优先。

### 4. 最初 50 项不是自动全部通过

- 29 项可对齐来源中的本地学名标签候选；
- 10 项只有明确的名称提及，还未对齐具体分类单元；
- 11 项尚无精确对齐结果。

“未精确对齐”不等于资料没收录这株植物。
例如工作簿实际有“樟 / Camphora officinarum”“月季花 / Rosa chinensis”
“落花生 / Arachis hypogaea”；它们与草案称呼的对应关系需要有依据地核对，
不通过硬编码新俗名或直接合并园艺类群解决。
绿萝、龟背竹已新增明确的室内用途来源，但仍保留名称级待核对状态。

## 可复现提取

新增一个离线脚本，不改 Flask 依赖、不新增 CI/服务：

```sh
uv run --locked --script server/scripts/build-plant-candidates.py \
  --output server/.cache/research/everyday-candidate-pool-next
```

脚本使用隔离的 uv 环境；`build-plant-candidates.py.lock` 固定依赖。
输入是已有本地公开资料，运行时不请求网络、不读取私人手账、不加载识别模型。
输出目录必须不存在；输入按 SHA-256 校验。

实际处理的两个提取问题：

- 黑龙江 PDF 第 6 页文字下划线被误识别为额外表格边界；使用经核验的固定列网格和
  序号列真实横线重建，完整提取 1–114，缺号/重复号即失败。
- 上海栽培工作表因格式信息宣称有 16,379 列，实际只有 21 个数据列；
  使用明确的工作表 schema，避免遍历大量空列或误读字段。

北京跨页作者片段合并时保留所有源页码。
PDF 三表及上海两表的序号均逐项检查，不悄悄忽略解析失败行。
