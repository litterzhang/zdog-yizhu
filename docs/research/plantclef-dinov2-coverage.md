# PlantCLEF DINOv2 类别覆盖核查

日期：2026-09-21。状态：已取得官方类别文件并完成本地只读比对。
**没有下载权重、加载模型、测量识别准确率或切换线上方案。**

## 结论

不建议将这个 PlantCLEF DINOv2 分类模型作为一株的主模型：

- 官方分类表实际为 **7,806 个类别**。
- 与一株 **19,716 个可见物种**保守匹配 **2,427 个，约 12.31%**。
- 木犀／桂花、银杏、荷花木兰、绿萝、茉莉的学名没有直接匹配。
- 适合考虑作为部分重合物种的辅助分类／召回分支，不适合替换广覆盖主流程。

这里的 12.31% 是类别表匹配比例，**不是准确率**；没有做完整学名异名桥接。
即使 7,806 类都能一对一对齐到不同可见物种，也仅相当于当前目录的 39.59%。
这只是分类头的类别覆盖上限，不限制 DINO 视觉特征被用于其他物种的检索或微调。

## 一、核查的是哪个模型

官方发布记录：DOI `10.5281/zenodo.10848263`，发布日期 2024-03-21。
标题为 *PlantCLEF 2024 pretrained models on the flora of the south western Europe
based on a subset of Pl@ntNet collaborative images and a ViT base patch 14 dinoV2*。
这是 PlantCLEF 后续任务页指向的特定公开基线，**不是宣称它是最新或最强的植物模型**。

模型包中有两种训练方式：

1. `vit_base_patch14_reg4_dinov2_lvd142m_pc24_onlyclassifier`：
   冻结 DINOv2 backbone，仅训练分类头。
2. `vit_base_patch14_reg4_dinov2_lvd142m_pc24_onlyclassifier_then_all`：
   在前者基础上继续训练整个模型。

两份配置均声明 7,806 类，并使用 EMA。共享的官方映射文件为：

- `class_mapping.txt`：7,806 行、7,806 个唯一来源物种 ID。
- `species_id_to_name.txt`：7,806 个唯一 ID 与带命名人信息的学名，全部类别均可对应。

示例程序说明了 `输出索引 → 来源物种 ID → 学名` 的映射。
本轮只读取程序，没有执行其推理、联网图片读取或 checkpoint 加载。

## 三、比对方法与误差边界

1. 读取类别索引和来源 ID，不按中文名称连接。
2. 来源学名含命名人，例如 `Hydrangea macrophylla (Thunb.) Ser.`。
   本轮仅解析普通双名，保守去掉可识别的作者后缀。
3. 与目录的 `scientific_name` 做严格字符串匹配；不做模糊纠错、
   同属替代、杂交符号删除、亚种折叠或未验证的科学异名连接。
4. 无法保守解析的 310 条不计入覆盖；其中也包含少量作者前缀形式未被解析器接受的普通种，
   例如 `de Noé`、`d'Urv.`。因此不能把这些全说成“都是杂交种或亚种”。
5. 没有歧义双名被先到先得地合并；两份来源表 ID 唯一且无缺失映射。

**2,427 是当前规则下的保守交集，不是物种真实重合的绝对上限。**
学名异名核实可能增加匹配，但不能把候选关系直接当作确认。
同时，表中没有某个名称也不能说明通用 DINO 特征无法表示这种植物。

本轮使用的目录 SHA-256：
`38faa0c3f0da61d74bbfde82a97a203a9553fbd93606fe47e1d173de3067f910`。
可复核计数、匹配规则、来源校验值和样本索引见
`plantclef-dinov2-coverage.json`。

## 四、许可、下载和运行约束

### 许可

Zenodo 该模型记录的 `license.id` 为 `cc-by-4.0`，
DataCite 对同一 DOI 的许可元数据也为 **CC BY 4.0**。
这是明确的模型发布记录许可，不再只是根据代码仓库许可证猜测权重许可。
使用时保留作者、DOI、许可链接和修改说明；训练照片的逐图许可仍单独处理，
不能因模型许可就批量复制照片建立图库。

### 本轮没有下载大模型

发布包大小为 **2,271,216,640 字节**。用公开下载地址的 HTTP Range
仅读取 tar 头、类别／学名表、配置、说明等小文件，跳过 checkpoint 和照片内容；
服务端必须返回正确的 206 与 Content-Range，否则停止，不退化为整包下载。

从模型 archive 实际读取 **437,687 字节**，另读取少量公开元数据。
完整 archive 的发布方 MD5 是 `42bc1bf3725ebe0bc93a2167c6b3deda`，
**本轮没有下载完整文件，因此没有验证这个整体 MD5**。
小文件的本地 SHA-256 已记录在配套 JSON；不能把它冒称为发布方逐文件签名。

### 部署仍有未验证项

- tar 头显示两份 checkpoint 文件分别为 788,838,818 与 1,481,641,544 字节。
  这是文件大小，不是推理常驻内存，也不是实际运行测量。
- 发布记录使用 timm 0.9.16、torch 2.2.1+cu121；项目当前 timm 为 1.0.29。
  本轮没有为了对齐旧环境而降级线上依赖。
- 两份 args 没有显式指定 input_size；示例按模型配置获取预处理。
  本地已安装 timm 对该架构默认配置为 518×518。
  真正部署前须核实训练版本配置，不能擅自缩成 224×224 后仍宣称复现官方模型。
- `.pth.tar` 尚未加载。后续需要安全的权重读取、EMA 选择及兼容验证；
  不直接执行发布包里的示例程序，不为加载未知对象关闭安全限制。
- 尚未测 CPU 时延、内存、域外拒识或中国常见植物准确率。

## 五、对下一步方案的影响

用户后续确认：PlantCLEF 作为第一级不确定时的第二级本地辅助方案，
取消第三层 LLM／Jev 兜底；两级仍不可靠则返回待确认。
这项决定不改变本报告的覆盖限制。后续已实现可选的两级代码接线，
但正式权重与真实推理尚未验收，详见 `../recognition-cascade.md`。
流程约束见 `recognition-preprocess-recall.md` 的“已确认的兜底范围”。

### 近期主线：保持 BioCLIP，实施 preprocess + recall

继续 `recognition-preprocess-recall.md` 中的整图保留、多局部视图、
最多 100 个候选的方案。它不引入这个地域分类头的类别上限，
也不需要先下载、适配另一套权重。
这仍是待验证方案，不是因为这次目录核查就证明它更准确。

### 后续 DINO 分支：区分两件事

1. **PlantCLEF 分类头辅助分支**：只对可明确映射的类别输出辅助候选，
   与 BioCLIP 合并；不让其封闭类别 softmax 覆盖库外／非植物的不确定状态。
   对此次未直接映射的桂花、银杏等，它不能直接提供已知正确 ID 的分类候选。
2. **通用 DINO 图像检索分支**：使用通用视觉 backbone 配合带可靠标签的参考图库，
   重新计算该模型的图像特征；不受这 7,806 类分类头直接限制。
   代价是图库来源、逐图许可、标签和近重复去重；不能拿现有 BioCLIP 向量直接替用，
   也不能说已有中文目录就等于已有图像参考库。

如果后续要测试 PlantCLEF 分支，应把重合类别、未重合类别、非植物分别评估，
防止只挑它擅长的物种而夸大整体效果。所有真实效果仍需固定独立样本验证。
