# 将日常植物候选扩展到 1,000：来源与筛选研究

研究日期：2026-09-22。只研究选种，不恢复已暂停的图片采集或模型训练，
不修改生产目录。本文来源编号对应 `china-everyday-1000-sources.json`。

后续提取进展：已通过 NSII 公开链接取得上海工作簿及配套论文，并提取省市 PDF、
盆栽及室内用途线索，形成 3,026 个待核对候选标签。执行结果与缺口见
`china-everyday-candidate-pool.md`。下文“工作簿尚未取得”等为本研究阶段的历史状态，
不代表当前阻塞；千类训练范围仍未批准，训练继续暂停。

## 结论

可以从**多地区实际应用资料 + 园艺产品资料 + 地方常见野生植物调查 + 农业资料**
建立候选池，再筛选覆盖日常场景的约 1,000 个明确分类单元。
不是把现有 50 个称呼凭记忆补到 1,000，也不是换一个网站取观察次数前 1,000。

已发现足够广的候选资源；**尚未合并去重，不能宣称已取得 1,000 个有充分常见度
证据、且都有训练图片的物种**。当前 50 项仍只是需求种子，不能因名字熟悉直接获准训练。
建议名称用“中国日常场景植物识别集”，不叫“全国最常见植物排行榜”。

## 二、怎样扩展而不再次失真

### 1. 建立比 1,000 更大的候选池

先规划汇总约 2,000–3,000 个原始候选，留出异名、品种合并及证据不足的淘汰空间。
这是采集规划，不是已经计算出的数量。

- 先抓结构化工作簿、标准附表和有用途字段的名录，不大规模抓照片。
- 保存原始中文名、学名、页/表/行号、文件版本及证据原文定位；OCR 错字单列。
- 来源只读引用与内容再分发权限分开核实，不默认公开 PDF/图鉴照片可训练。
- 保留目前没中文名、没匹配现有目录或缺训练照片的候选，记录缺口，不悄悄删除。

### 2. 把“常见”拆成证据类型

建议使用简单、可审核的类别，不先发明加权总分：

| 类型 | 例子 | 建议处理 |
| --- | --- | --- |
| A 实测常见/应用 | 地区调查写明常见，或公开应用数量/地点 | 可作为核心证据，但只对原地区/场景有效 |
| B 已有常用用途 | 当地常用园林列表、主要盆花产品明确条目 | 进入重点候选；跨地区资料交叉核实 |
| C 推荐/适生 | 绿化推荐名录、引种试验推荐 | 作为补充来源，寻找实际应用证据后晋级 |
| D 单纯收录/存在 | 地方植物志、植物园收藏、标本记录 | 只证明存在与分类，不直接批准常见种 |

一份高质量区域调查可支持一个地区的重要物种，不要求每种都跨全国出现。
但仅有一份适生推荐或收藏记录不能为补足 1,000 而自动晋级。
同一名录被十个网站转载仍只算一个来源。

### 3. 用场景约束覆盖，而不是野外观察数统治名单

以下是**可调整的产品规划目标，不是调查结果或硬性凑数指标**：

| 主场景 | 目标 |
| --- | ---: |
| 街道、公园、校园 | 300 |
| 庭院、室外观赏花木 | 250 |
| 室内、阳台盆栽 | 150 |
| 路边、郊野常见植物 | 200 |
| 农作物、蔬菜、果树 | 100 |
| 合计 | 1,000 |

每个确认的分类单元只计一次；可以拥有多个场景标签，但只能有一个用于配额的主场景。
例如同时出现在庭院、公园的同一物种，不应占两个名额。
若某类证据不足，先报告缺口并调整目标，而不是往名单塞偏门品种。

### 4. 地域和生活场景交叉检查

覆盖检查至少包括东北、华北、华东、华中、华南、西南、西北；
再区分城区、乡村/农田、郊野和室内，而非只用沿海城市名录。

优先对各区选择不同气候/城市层级的资料，随后看物种增量和重复率：
新增来源若只是重复现有树种，就应转向缺口场景，而不是继续累计网页数。
从 F01/F11/F12 及其附件扩展东北、华中；四川入口已发现，正文尚未核实。
西北线索 F14 已失效，需要替换，不能把失败链接算作已覆盖一个地区。
这些尚不构成“七区覆盖已完成”。

国内植物与日常使用的外来栽培植物均可入选；本项目不是乡土植物限定目录。
不能机械复制绿化选种的“推荐/慎用”作为识别服务的允许/禁止规则。
只有全国观察记录频次高而无应用依据的物种，不再自动排在前列。

## 三、从“称呼”变成可训练的标签

每个来源条目经过：原始名 → 学名核对 → 接受名/异名处理 → 分类范围确认 →
稳定 Species ID 对齐。名称显示和训练标签分别管理。

- 同一物种的中文俗名、学名异名合并，保留每次合并的依据。
- 源表上的栽培品种不能逐条作为不同物种计算；有明确归属时归并至父分类单元。
- 明确的杂交分类群可以单列，但要保留杂交身份，不伪装为普通物种。
- 只到属级、宽泛园艺名或混合商品名，先进入待核对表，不强配给某个已有物种。
- 不用一个属级训练类与其多个种级类组成相互重叠的平面标签；属级可用于界面解释/拒识。
- 现有数据库没匹配成功是名录完善任务，不是候选“不常见”的证据。
- “恰好 1,000 个可显示的中文名”不等于“1,000 个互斥、可学的图像分类标签”。

建议统一记录：

```text
candidateId / acceptedTaxonId / speciesId / rank / scientificName
displayName / aliases / nameSources / taxonomicDecision
primaryScene / sceneTags / supportedRegions
evidenceType / sourceId / sourceVersion / pageOrRow / selectionReason
selectionStatus / photoAvailability / trainingReadiness
```

## 四、名单与训练集分开验收

先冻结经过证据与分类核对的识别范围，再检查每类可获取的授权图像。
保留 `selected-but-data-missing` 状态：不能因为图片少，把日常重要物种静默换成容易下载的野草。

### 只改名单仍不够：旧采图条件也必须调整

本地 `training_data.py` 的请求与样本验证均限定 `quality_grade=research`。
iNaturalist 的官方项目筛选公告（F22）明确区分因非野生而成为 Casual 的记录；
只保留 Research Grade 的路径无法覆盖这些栽培记录。
不能换了新千种名单，却保留旧筛选再把缺图的园艺植物删掉。

2026-07-14 官方公告（F22）新增集合项目筛选，可只纳入因非野生而成为 Casual 的记录，
同时排除缺照片、缺日期等其他原因的 Casual 记录。这表明来源端已有区分机制；
**本轮只核实官方项目功能，未验证对应 API 参数或实现采集改动**。
后续应分野生和栽培两条取样路径，分别校验标签、鉴定依据和逐图许可；
不是把所有 Casual 数据无审核放进训练。必要时使用获得授权的园艺来源或人工核对，
不能把是否 Research Grade 当作唯一标签质量判定。
F21 帮助正文在本轮未成功打开，不把该链接当作已经阅读全文的证据。

旧流程每类 20/5/5 图只是训练链路冒烟门槛，**本研究不把它视为千类模型的充分数据标准**。
建议后续按类别难度、多样性和学习曲线决定图量，并单独检查：

- 中国实际拍摄场景、不同地区/季节、花/叶/整株视角是否覆盖；
- 近缘种、园艺类群是否真的能从当前照片区分；
- 按观察/观察者分组及近重复去重；不能只随机拆分图片；
- 库外植物、非植物、细节不足的照片能否保持不确定；
- 以地区、场景、物种分别报告测试结果，不把三类冒烟分数当千类准确率。

这些是下一阶段的验收设计，不是本轮已执行的训练或精度测试。

## 五、具体落地顺序与研究边界

1. **先取得来源表**：上海原始工作簿、北京/深圳附表、正式盆栽植物标准正文，
   同时通过林草局专题补东北/华中/西南/西北；下载失败记阻塞，不绕过访问控制。
2. **先处理一批有证据的核心条目**：用来检验分类、别名、地域和场景分组是否合理，
   不再称手写 50 项为“已核验核心物种”。
3. **扩大候选池并去重**：输出按场景/地域的覆盖报告、来源分级和所有被排除的理由。
4. **冻结约 1,000 个分类单元的目标清单**：证据不足则交付实际确认数量及缺口，
   不以数量压倒可靠性；用户确认后再启动数据与训练。
