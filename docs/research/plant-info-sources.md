# 植物中文常用名、别名与资料补全调研

调研日期：2026-09-21。本文件记录首轮公开资料核实与只读数据比对。

后续进展：已取得并校验 ScienceDB 原文件，别名及 8,438 个缺名物种的补名／可见性已上线，见
`../name-enrichment.md`。下文期刊附件统计仍保留为首轮研究证据；
与后续使用的 ScienceDB 原文件不同，不能混用两个快照的数量。

## 结论与建议

没有验证到一个同时满足“全球完整覆盖、可靠中文别名、详细中文介绍、明确可复用许可”的单一数据源。
建议组合使用：

1. **全国名录**继续提供首选中文名和分类；不覆盖已有名称。
2. **中国外来植物名录数据集**补充园艺、引入植物的中文名称和别名；使用已核验的 DOI 原文件。
3. **Wikidata 有文献引用的俗名声明**补充“桂花”等常用名；不能直接照收所有标签和别名。
4. **植物智／中国植物志**用于名称核实和简介来源线索；未确认批量复用授权前，不整站采集正文。

“更完整的资料”与“识别更准确”是不同任务。本轮不调整 BioCLIP、候选排序或可见性。
所有名称只关联 Species，绝不能据此合并现实中的 Plant 个体。

## 首轮研究基线（历史快照）

根据现有文档及本轮读取的公开参考库：

- 全国 XLSX 有 48,356 条记录，不包含俗名／别名列或形态描述列。
- 现有参考目录有 108,372 个条目；11,278 个可见，97,094 个隐藏。
- 当前只接受全国名录中文名，`chineseAliases` 为空；已有 6 条带来源的物种摘要。
- `Osmanthus fragrans` 在全国文件中是“木犀”，没有“桂花”这个精确中文种名。
- “全国名录没有桂花这个首选名称”不等于“没有收录桂花这一物种”。

基线文件：`docs/national-names-and-descriptions.md`、`docs/chinese-names.md`。

## 一、中国外来植物名录数据集：最值得先做批量补全

作者林秦文、崔晓、马金双；数据 DOI `10.57760/sciencedb.01711`，版本 V1，
关联论文 DOI `10.17520/biods.2022127`。[S1–S3]

本轮实际从期刊公开附件下载 ZIP，并用标准库读取其中 XLSX，没有安装新依赖。
实测 **14,710 条数据、15 列，其中 2,910 条别名非空**。列包含中文名、别名、学名、
命名人、科属、生存状态、生活型、原产地与引入省份；没有详细形态或花期正文。

值得注意：论文说明写的是 14 列；附件实际多出一列“2018 年入侵植物名录”。
因此不能只依赖论文摘要定义导入格式。

### 与现有目录的只读交集

仅去除来源学名前后空白，与 `species.scientific_name` 精确相等：

| 指标 | 参考条目数 |
| --- | ---: |
| 能匹配的现有条目 | 10,327 |
| 其中当前可见 | 1,291 |
| 其中当前隐藏 | 9,036 |
| 匹配且来源别名非空 | 2,335 |
| 当前可见且来源别名非空 | 244 |

来源学名没有重复字符串。以上**不是已通过分类审核的可导入数量**：
尚未处理等级、杂交种、异名关系和名称冲突，也不是识别率或全球覆盖率。
隐藏条目补中文名仍需用户批准扩大来源范围，不会因本次研究自动显示。

实际例子：附件第 581 行 `Magnolia grandiflora` 的中文名是“荷花木兰”，
别名为“荷花玉兰”；第 722 行 `Epipremnum aureum` 是“绿萝”，别名为空。
不能为了补齐而生成缺失别名。

### 许可与版本限制

DataCite 的该 DOI 元数据和 ScienceDB 页面内该数据集的 JSON-LD 均声明
**CC BY 4.0**；JSON-LD 同时标记 PUBLIC。导入须保留作者、DOI、许可和修改说明。
不能把页面中其他许可的通用帮助文字误判为该数据集的许可。

不过，ScienceDB 列出的 XLSX 是 1,408,491 字节，MD5 为
`2119022b9aea4f0d014ff98fec0c2518`；期刊 ZIP 内 XLSX 是 1,582,916 字节，
二者显然不是同一二进制快照。首轮 ScienceDB 文件下载超时；
随后重试已取得原文件并通过发布方 MD5 校验。原文件为 14 列、2,909 条非空别名，
有少量名称差异。离线工具使用 DOI 原文件，不将其许可元数据套到期刊附件版本。

期刊 ZIP：1,454,153 字节；SHA-256：
`e0dcc2460dea6995ff4b1b9ab78e9fbc6166e7c3da1ee3d7ee424158a2900457`。
不再分发整份附件，也不把它加入生产资源。

## 二、Wikidata：有实际中文名，但要选择声明而非全部照收

官方许可说明将结构化实体数据置于 **CC0**；这不代表 Wikipedia 文章、
引用图书全文或照片也都是 CC0。[S4–S5]

本轮用 6 个公开学名和物种等级进行精确查询，返回 5 个实体，随后下载其实际 JSON：

| 学名 | 实体 | 中文标签／别名样本（未导入） |
| --- | --- | --- |
| Osmanthus fragrans | Q1209922 | 桂花；木犀、木樨 |
| Magnolia grandiflora | Q161116 | 荷花玉兰；荷花木兰、广玉兰 |
| Hydrangea macrophylla | Q159219 | 简体标签“绣球”；八仙花 |
| Epipremnum aureum | Q161809 | 绿萝；黄金葛 |
| Ginkgo biloba | Q43284 | 简体标签“银杏”；白果、公孫樹 |

这是定向可行性样本，不是随机覆盖率调查。
`Hibiscus rosa-sinensis` 未通过本次查询条件，不说明它没有中文名。
保留原语言、字形，不恢复此前移除的自动繁简转换或手工别名表。

### “桂花”的逐条来源

`Q1209922` 的 `P225` 是 `Osmanthus fragrans`，`P105` 为物种；
本轮快照 revision 为 `2547139348`。
其 `P1843`（taxon common name）有“桂花”和“木犀”声明，
引用 `Q112869463`《中国植物志》第六十一卷及第 107 页。
本轮读取了该引用实体，确认卷名；没有声称已经核读该卷原书第 107 页。[S6]

相比普通 `aliases`，这类声明可以保存 statement ID、参考文献、页码和语言。
但“有引用”仍不等于“可无条件接受”：同一实体也有“桂花根”“桂花露”等声明；
普通 aliases 中还有“丹桂”“九里香”。前者可能是部位／加工物，后者需要确认
园艺范围或同名歧义。银杏 aliases 中甚至有“银杏叶提取物”。
因此先进入待审数据，不自动变成同义物种名。

免费公开访问不等于无限请求。官方推荐小批量实体访问，大量数据使用 dump。
一株宜离线分批、缓存 revision、限速与失败退避，不在识别请求中实时查询 Wikidata。
本轮没有全量下载、全库匹配或统计全量中文别名覆盖率。

## 三、植物智／中国植物志：可以证实俗名，正文授权待明确

本轮直接请求植物智 `Osmanthus fragrans?t=h` 成功，实际 HTML 标题为木犀，
俗名区确有“桂花”，并将中文俗名与拉丁异名分开展示。[S7]
这次取得的是网页正文，不是搜索摘要；与此前失败的抓取不同。

但页面的植物志内容存在动态加载。本轮 `?t=z` 取得相同页面外壳，
不能据此声称已抓到完整《中国植物志》形态段落。
页脚声明版权所有；尚未确认可用于本项目的公开批量 API 或正文复用许可。
可作为人工核实出处，详细资料批量接入仍须取得许可或明确开放数据条款。
不绕过验证码、认证或访问控制，也不照抄整篇介绍。

## 四、暂不作为首批来源

- **iNaturalist Taxonomy**：GBIF 实际元数据确认数据集 ID 为
  `738041eb-6a2d-449f-8007-0ee4793195d3`，许可 CC BY 4.0。[S8]
  这是分类数据集，不是 Research-grade Observations。
  本轮其 GBIF 数据集接口的 endpoints 为空，限定该数据集的木犀搜索返回 0；
  尚未验证中文 VernacularName 扩展或批量归档，不据此推断它没有中文名。
- **Kew POWO／WCVP**：仅列为后续接受学名／异名关系研究候选。
  本轮官方引用页直接访问为 403，未核实可下载版本和适用许可，不列为已可接入来源，
  更不能承诺它提供完整中文俗名。
- **TaiCOL、手工名称配置**：按此前决定不恢复。聚合源记录若仅引用排除来源，
  或来源链不明，先隔离；不能宣称整个聚合源都没有间接来源。
- 宣传“全部中文名”“接近 100%”的第三方词表，若无法追踪命名依据、许可及是否
  机器翻译，不作为中文名权威来源。

## 五、简介如何补齐

把公共 `Species.knowledge` 与私人 `Plant.description`／story／观察文字分开。
建议先补可核实事实，不追求每种都自动生成一篇百科：

1. 来源记录保存学名、原始字段、来源版本、许可和记录位置。
2. 名录能支持分类事实；外来植物数据能支持原产地、生活型等有编码说明的事实。
   没有核实编码释义之前不能自行猜测；历史引入范围不当作当前实时分布。
3. 叶、花、果特征与花果期须另找允许复用且能定位物种的资料。
   未知则留空；花期有地区条件，不生成全国统一月份。
4. 按允许的使用范围整理简短中文摘要，保存逐条出处、更新时间和复核状态。
   AI 仅可辅助表达已验证事实，标记 `isAiGenerated=true`，不能补造事实或来源。
5. 不复制受保护正文，不提供食用／药用保证，不从照片推断树龄。

当前尚未找到经实际下载、验证许可、可全量直接使用的完整中文形态介绍库。
Wikidata 的简短实体 description 不能冒充详细植物介绍。

## 六、只改服务端的落地方案（尚未执行）

保持现有接口：`chineseAliases`、`nameSources`、`knowledge` 已存在。
中文首选名继续由全国名录提供；先给已有可见物种补别名。
新增来源的内部元数据不要随意塞入现有 `chineseNameOrigin` 联合类型。
未来若要给隐藏物种使用非全国来源作首选名，应单独验证兼容并取得批准。

导入记录最少保留：
`speciesId / scientificName / rank / name / nameKind / language / sourceId /
sourceRecord / revision / license / retrievedAt / reviewStatus`。
源数据缓存与已接受的名称索引分开；不做一个永久人工 if/else 名称表。

- 科学异名与中文别名分表；分类连接只用精确学名、等级或有来源的接受名关系。
- 一个中文词可以对应多个物种；不把俗名设为全局唯一，也不据此合并 ID。
- 来源冲突、品种群、药材／部位／加工物词条进入待审；默认不自动覆盖。
- 搜索优先精确首选名，其次已接受别名；重复名字显示学名消歧。
- 存量 Species／Plant ID、向量映射和原始 Recognition 返回不变。
- 在独立目录快照中统计新增／冲突／跳过／可见性差异，通过后才替换，旧快照可回滚。
- 无按次外部 API 费用；仍有下载、存储、定期更新和核对成本。

小型离线补全入口现已实现，没有增加在线微服务，说明见 `../name-enrichment.md`。
候选快照不等于生产导入；确认覆盖与冲突后，另行决定首选中文名来源及隐藏条目的显示范围。

## 七、本轮实际执行与限制

- 查阅仓库规范、现有数据文档、客户端类型和后端资料校验器。
- 网页浏览工具没有返回可用内容，改用获授权的 HTTPS 请求读取上述官方公开页面及 JSON；
  没有依赖不可见的搜索结果。访问失败和许可未决项均在上文列出。
- 下载期刊附件，用 `zipfile`／XML 读取并计数；SQLite 以 `mode=ro` 查询公开参考库。
- 原始缓存位于被忽略的 `server/.cache/research/plant-info-20260921/`；
  精简可复核指标见本目录 `plant-info-samples.json`。
- 仅新增研究文档／摘要，并更新平台进度。没有访问私人照片、用户记录或密钥，
  没有生产导入、重启、客户端改动、构建、测试、微信上传或收费资源开通。
