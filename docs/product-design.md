# 阶段 1：白纸上的自然观察手账

## 产品边界

认识物种，也记住现实中某一株植物。不做电商、聊天、公共社区、病害诊断、食药鉴定或树龄判断。档案以私有为目标，本阶段完全在本地会话中演示。

本轮只交付首页、识别结果、植物档案三个视觉样板。先评审白色、照片与克制手绘风格，再展开全部页面。建档与追加观察在三页内可演示，但不是阶段 2 的完整、持久化 MVP。

## 页面流

1. 首页 → 相机 / 相册 / 示例图 → 本地图片预览 → 显式开始演示识别。
2. 识别结果 → 假候选 / 失败 / 无法判断 → 用户手动确认物种，或保留未知。
3. 结果 →「记住这一株」→ 昵称必填、地点与故事可选 → 新个体 ID + 首次观察。
4. 结果 →「关联已有植物」→ 选择档案 → 再次确认是同一株 → 追加观察，不覆盖档案物种。
5. 档案 →「记录新变化」→ 选图与可选笔记 → 追加到同一个 Plant ID。
6. 返回首页 → 最近观察或最近识别可继续查看；清空操作有确认提示。

计划中的正式导航为「发现 / 我的植物 / 我的」，本轮不制作未实现导航占位。

## 数据模型与不变量

| 实体 | 职责 |
| --- | --- |
| Species | 稳定物种 ID、中文名/学名、可空分类与可空知识来源 |
| Recognition | 识别任务 ID、用户、照片、状态、原始 provider 结果、独立的用户确认 |
| Plant | 系统生成个体 ID、所有者、昵称、可空物种、地点、故事、封面 |
| Observation | 植物 ID、所有者、观察时间、照片、笔记、可空识别关联 |

- 昵称、坐标、物种、照片哈希都不是 Plant ID；重名仍是独立个体。
- 物种候选不会自动成为档案的已确认物种；修改用户选择不覆盖原始候选。
- 相同物种、近似位置、相同照片都不自动触发个体合并。
- 建档重复提交在会话中按识别 ID 幂等；关联按植物 ID + 识别 ID 幂等。
- 照片作为独立引用建模；后续删除历史不能删除仍被档案或观察引用的文件。
- 样板 ID 为本地会话生成；生产 ID 和 owner 必须由可信后端控制。

## 视觉系统

- 白底 `#FFFFFF`、次背景 `#F7F8F5`、正文 `#253129`、次文字 `#667168`。
- 操作绿 `#496B50`，分隔线 `#E7ECE5`；其他颜色只作少量提示。
- 以 375 设计宽度编写 px，由 Taro 转换为微信端 rpx。
- 标题约 25px，正文 14–15px；系统字体，不以手写字承载关键信息。
- 间距以 4/8/12/16/24/32 为基础；按钮高度至少 48px，次级文字按钮至少 44px。
- 照片是主角；详情图片支持完整预览。原创线稿只出现于首页与空状态。
- SVG 仅作为设计源文件，应用使用预先导出的静态 PNG。
- 使用原生导航栏保留状态栏、胶囊空间，页面底部保留 safe-area。
- 不做虚构识别进度百分比、扫描动效或持续漂浮装饰。

## 状态与已知边界

选图有取消、权限拒绝、失败、大小超限；图片有加载、失败和重试。识别有 running / succeeded / uncertain / failed。会话重置后访问失效 ID 有返回首页路径。清空会话可查看首页空状态。正文允许换行，输入有字符限制。

没有云读取，因此档案本身不模拟虚假的网络加载。网络超时恢复、跨会话识别任务、持久化、全部 CRUD、搜索、用户退出隔离与生产删除仍属后续阶段。当前只验证本地逻辑，不能宣称云端权限已安全。
